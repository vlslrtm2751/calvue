# 그룹웨어 캘린더 동기화 Phase B (오늘 포커스) 설계

**목적:** '오늘' 버튼이 실제로 오늘로 데려가고 잠깐 강조하게 만든다. 지금은 앵커만 옮겨서, 이미 오늘이 속한 기간을 보고 있으면 눌러도 아무 반응이 없다.

## 배경

`saeroun-gw-web`(형제 프로젝트) 캘린더 변경을 calvue에 역이식하는 6개 phase 중 네 번째다. Phase A(버그 수정, v0.2.0)와 Phase C(툴팁 슬롯 + 팝오버 수정)는 완료됐다.

**원칙**: 원본 코드를 옮기지 않는다. calvue는 `vue`/`dayjs`/`@vueuse/core`만 peer로 두는 자체완결 라이브러리이고, **그룹웨어는 calvue를 채택하지 않고 독립적으로 존재한다**(사용자 결정, 2026-08-15). 업스트림 커밋은 "맞춰야 할 사양"이 아니라 **버그 리포트이자 설계 힌트**다.

### 이 기능의 원래 존재 이유

사용자 증언: **목록 뷰에서 '오늘'을 눌렀을 때 오늘 날짜의 일정으로 이동하게 하려고 만들어진 기능**이다. 일/주/월 뷰에서는 강조가 더 눈에 띄는 역할이었다. 따라서 **목록 뷰의 스크롤이 이 기능의 중심**이고, 강조는 보조다. 설계 판단이 갈릴 때 목록 뷰 쪽을 우선한다.

## 핵심 결정 — 자동 소멸

**강조는 2초 유지 후 0.5초에 걸쳐 사라진다.** 업스트림은 타임아웃이 없어 사용자가 다른 조작을 할 때까지 무한히 남는다(그쪽 문서에는 "잠시 강조된다"고 적혀 있지만 코드에 타이머가 없다 — 문서가 틀렸다).

이 결정이 **업스트림의 구조적 결함을 통째로 제거한다.** 업스트림은 강조가 영원히 남기 때문에 "이럴 땐 꺼야 한다"를 10군데에 손으로 열거해야 했고, 빠뜨린 조건을 **다른 개발자가 이틀 뒤 커밋 두 개로 메웠다**(`4a23bc236`, `ec4ea9ad7`). 열거식 해제는 새 상호작용이 생길 때마다 조용히 빠뜨리게 되는 패턴이다.

수명이 2.5초면 그 목록이 대부분 저절로 불필요해진다:

- 다른 기간으로 이동 → 대부분은 오늘이 더 이상 렌더링되지 않아 강조 대상 자체가 없어짐. 다만 월 뷰는 인접 달의 여분 날짜(흐리게 표시되는 muted 셀)도 함께 그리므로, 2.5초 안에 옆 달로 넘기면 오늘이 그 muted 셀로 남아 강조가 계속 보일 수 있음 — 이 경우도 타이머가 곧 꺼주므로 자연히 해소됨
- 일정 클릭 → 2.5초면 알아서 꺼짐
- 드래그·선택 중 → 주/일 뷰는 진행 중인 제스처(`.tg-select`/`.tg-preview`, `z-index: 110`)가 강조 위에 그려져 가려짐. 월 뷰는 반대로 강조 오버레이(`::after`)가 선택 배경(`.cal-month__cell--sel`)보다 위라 강조가 계속 보이지만, 어느 쪽이든 2.5초 안에 강조 자체가 자동으로 사라지므로 남는 문제가 없음

**따라서 `clearTodayFocus()`류의 해제 로직을 일절 만들지 않는다.**

### `clusterOpen` / `moreOpen`은 만들지 않는다

Phase C가 `clusterOpen`을 "Phase B 의존"으로 미뤄뒀다. 그 이벤트의 유일한 존재 이유가 "팝오버가 열릴 때 오늘 강조를 해제"이기 때문이다. 해제 자체가 없어졌으므로 **구현이 아니라 불필요로 종결한다.** `moreOpen`도 같은 이유로 만들지 않는다.

## 동작

### 트리거

'오늘' 버튼(및 `defineExpose`의 `today()`)을 누르면 세 가지가 일어난다:

1. 앵커를 오늘로 이동 (기존 동작)
2. 오늘 강조 켜짐 → 2초 뒤 0.5초에 걸쳐 페이드아웃
3. 오늘이 보이도록 스크롤

**이미 오늘을 보고 있어도 2·3이 일어나야 한다.** 이것이 이 작업의 핵심 요구사항이다.

페이드아웃은 CSS `transition`으로 처리하고, `prefers-reduced-motion: reduce`면 즉시 사라지게 한다.

### 뷰별 스크롤 정책

| 뷰 | 정책 |
|---|---|
| **목록** | 오늘 행을 스크롤 컨테이너 맨 위로. `.list-month`가 `position: sticky`이므로 그 높이만큼 뺀다 |
| **주/일** | 현재 시각이 세로 중앙에 오도록. 오늘이 표시 범위에 없으면 스크롤하지 않는다 |
| **월** | **오늘 칸이 이미 다 보이면 스크롤하지 않는다** — 맨 위로 올리면 앞선 주들이 가려진다 |

월 뷰의 "안 움직임" 정책은 업스트림에서 "버튼이 밋밋하다"는 문제가 됐다(색만 바뀌고 끝). **자동 페이드가 있으면 그 반짝임 자체가 피드백**이 되므로 이 조합에서는 문제가 되지 않는다.

**주/일 뷰의 `TimeWindow` 주의점**: Phase A에서 도입한 `slotMinTime`/`slotMaxTime` 때문에 현재 시각이 그리는 창 밖일 수 있다(예: `slotMinTime: '09:00'`인데 지금 07시).

**처리: 스크롤 위치를 유효 범위로 클램프한다. 별도 분기를 두지 않는다.** 목표 위치를 `Math.max(0, nowTop - clientHeight / 2)`로 계산하면 현재 시각이 창 시작보다 이르면 `nowTop`이 음수가 되어 0(창 맨 위)으로 클램프되고, 창 끝보다 늦으면 브라우저가 최대 스크롤에서 자연히 멈춘다. 즉 **창 밖으로 스크롤되는 일은 구조적으로 발생하지 않으며**, 결과는 "창의 가장 가까운 끝"이라는 합리적인 위치다. 특수 케이스 코드가 필요 없다.

스크롤 동작은 `smooth`, `prefers-reduced-motion`이면 `auto`.

### 스크롤 대상 찾기

**calvue에 이미 있는 관례를 그대로 쓴다.** `data-cal-date="YYYY-MM-DD"`가 월 뷰 셀(`cal-month-view.vue:30`)과 주/일 뷰(`cal-time-grid.vue:23,71`)에 이미 있고, `use-calendar-dnd.ts`가 드롭 대상 판정에 이 속성을 이미 쓰고 있다. 새 규칙이 아니다.

**목록 뷰에만 빠져 있으므로 추가한다.** `dateKey`가 이미 `YYYY-MM-DD`로 계산돼 있어 값도 그대로 쓴다.

주/일 뷰는 DOM 조회 대신 산술로 계산한다 — "몇 번째 날 칸"이 아니라 "현재 시각이 세로 어디쯤"이라 좌표 계산이 자연스럽고, Phase A의 `pctOf`/`nowMin` 계산을 재사용할 수 있다.

## 상태 모델

```ts
const todayFocused = ref(false);   // 강조 표시 여부
const focusSeq = ref(0);           // 스크롤 신호 (누른 횟수)
```

**`boolean` 하나로는 안 되는 이유** — 이 기능의 핵심 함정이다.

`today()`는 `anchor.value = dayjs()`를 한다. 그런데 **이미 오늘이 속한 기간을 보고 있으면**(마운트 직후의 기본 상태이기도 하다) 앵커 값이 바뀌지 않고, 따라서 `days`·`weeks`·`range` 어느 것도 바뀌지 않고, **어느 뷰의 어떤 반응형 의존성도 건드려지지 않는다.** 관찰할 대상이 존재하지 않는다.

`todayFocused` 하나로도 부족하다. 이미 `true`인 상태에서 다시 누르면 `false→true` 전이가 없어 watcher가 침묵한다.

**증가하는 카운터는 값과 무관하게 매번 엣지를 만든다.** "눌렸다"는 사실만 전달하는 채널이다.

### 흐름

```
today() ──> anchor = 오늘
         ├─ todayFocused = true  ──> 2초 뒤 false (타이머), CSS transition으로 0.5초 페이드
         └─ focusSeq++           ──> 각 뷰: nextTick 후 스크롤
```

`nextTick`은 앵커가 **바뀐** 경우에 필요하다. 그리드가 다시 그려지므로 그 전에 측정하면 옛 위치가 나온다.

### 뷰 prop

세 뷰 모두 optional prop으로 받는다:

```ts
todayFocused?: boolean;
focusSeq?: number;
```

각 뷰가 `focusSeq`를 watch해 자기 정책대로 스크롤하고, `todayFocused && day.isSame(today, 'day')`로 강조를 판단한다. 스크롤 정책이 뷰마다 다르므로 로직은 각 뷰가 갖고, **공통 부분(엣지 감지 + `nextTick` + 모션 정책)만 컴포저블로** 뺀다.

### 타이머

`useTimeoutFn`(`@vueuse/core`, 이미 peer dep이며 auto-import됨)을 쓴다. 재호출 시 이전 타이머를 자동 취소하므로 '오늘' 연타에도 마지막 것만 남고, 언마운트 정리도 자동이다.

### 업스트림에서 가져오지 않는 것

- **`loading` 재동기화 watcher** — 데이터 로딩이 끝날 때마다 스크롤을 다시 시키는 장치. 분석 결과 **이유를 불문하고 refetch가 일어나면 사용자를 오늘로 끌고 간다**(달력 표시 토글, 백그라운드 갱신 등). 강조가 2.5초면 꺼지므로 존재 이유 자체가 약하다.
- **`clearTodayFocus()` 10곳** — 위 결정에 따라 전부 제외.

## 목록 뷰 전제 조건

현재 `cal-list-view.vue`는 `if (dayEvents.length > 0)`으로 일정 없는 날을 걸러낸다. 오늘 일정이 없으면 **강조할 대상도 스크롤할 대상도 없다.** 세 가지가 먼저 필요하다:

1. **오늘은 일정이 없어도 행을 렌더링**하고 "일정 없음" 표시를 넣는다 (사용자 승인 완료)
2. **`.list-day` 행에 `:data-cal-date="group.dateKey"` 추가**
3. **`today`를 prop으로 받는다** — 현재 내부에서 `dayjs()`로 계산해 반응형이 아니다. 자정을 넘겨도 갱신되지 않는 잠재 버그가 이미 있고, prop으로 바꾸면 함께 해결된다

1번은 **눈에 보이는 동작 변화**다. 오늘 일정이 없던 소비자에게 없던 행이 생긴다. 릴리스 노트 필수 항목.

## 종일 행 배경 레이어 (`6a4943837`의 포커스 절반)

업스트림은 주/일 뷰 포커스 밴드가 종일 행에서 끊겨 보이는 문제를 겪었다. 종일 행의 셀이 **드래그 드롭 대상**이라 `inset: 2px`, `gap: 2px`, `border-radius: 4px`를 갖는데, 헤더·본문 밴드는 각지고 full-bleed라 폭도 모서리도 어긋났기 때문이다. 해결책은 `pointer-events: none`인 별도 배경 레이어를 `inset: 0`의 gapless 그리드로 깔아 컬럼 경계를 정확히 일치시키는 것이었다.

**calvue에 같은 문제가 있는지는 구현 중 실제로 확인한다.** calvue의 종일 행 구조가 업스트림과 다를 수 있다. 밴드가 끊겨 보이면 같은 방식(별도 레이어)으로 해결하고, 아니면 넣지 않는다. 미리 결정하지 않는다.

관련 교훈 하나: 업스트림에서 이 포커스 레일(진한 색)이 **기존에 있던 컬럼 정렬 어긋남을 드러냈다**. 그 어긋남 자체는 Phase A에서 이미 고쳤지만, 진한 세로 레일을 그리면 정렬 문제가 눈에 띄게 된다는 점은 QA에서 확인할 가치가 있다.

## 공개 API

**옵션도 emit도 추가하지 않는다. CSS 변수 하나만 늘어난다.**

```css
--cal-today-focus-bg   /* 기본: color-mix(in srgb, var(--cal-primary) 18%, transparent) */
```

기본값은 기존 `--cal-primary`에서 파생한다. 업스트림의 `rgba(var(--v-theme-primary), 0.18)`은 Vuetify가 색을 `R,G,B` 삼원색 문자열로 내보내기 때문에 가능한 방식이고, calvue의 `--cal-primary`는 완성된 색(`v-bind(primaryColor)`)이라 그대로는 쓸 수 없다. `color-mix()`면 새 토큰 없이 해결된다.

**변수를 여는 이유는 대비 문제다.** 강조 배경이 이벤트 뒤에 깔리므로, 소비자의 `primaryColor`가 밝으면 이벤트 글자가 읽기 어려워질 수 있다. Phase C 최종 리뷰도 업스트림 포커스 링에서 같은 문제를 지적했다. 탈출구 하나는 필요하다.

**넣지 않는 것과 이유:**

- 지속 시간 옵션 — 요구가 없다. 나중에 추가만 하면 되는 변경이고, 이 저장소는 쓰이지 않는 API를 미리 열었다가 제거한 전례가 있다(`more` emit, v0.2.0에서 제거)
- 기능 on/off 옵션 — '오늘' 버튼의 존재 이유가 오늘로 데려가는 것이라 끌 이유를 찾기 어렵다
- emit — 소비자가 포커스 발생을 알아야 할 이유가 없다

## 검증

vitest 없음(도입은 범위 밖). 태스크마다 `yarn typecheck`, 마지막에 `yarn build` + 플레이그라운드 QA.

**이번 기능은 타이밍·스크롤·시각 효과라 typecheck으로 잡히는 게 거의 없다.** Phase C에서 발견된 회귀 두 건이 모두 런타임 동작이었고 실제 브라우저에서만 드러났다. QA가 사실상 유일한 게이트다.

### 확인 항목

- **뷰 4종 × "이미 오늘을 보고 있을 때"** — 이 기능의 존재 이유. 앵커가 바뀌지 않는 경우에도 강조·스크롤이 일어나는가
- **연타** — '오늘'을 빠르게 두 번 눌러도 타이머가 겹치지 않고 마지막 것만 사는가
- **자동 소멸** — 2.5초 뒤 실제로 꺼지는가. 내부 상태가 아니라 **computed style**로 확인
- **목록 뷰** — 오늘 행이 sticky 헤더에 가리지 않고 맨 위에 오는가. **오늘 일정이 0개일 때도** 행이 있고 스크롤되는가
- **주/일 뷰** — 현재 시각이 세로 중앙에 오는가. **`slotMinTime`을 현재 시각보다 늦게 설정**해 창 밖 케이스 확인
- **월 뷰** — 오늘이 이미 보이면 스크롤하지 않고, 짧은 뷰포트에서 안 보이면 스크롤하는가
- **회귀 없음** — '오늘'을 누르지 않은 상태에서 기존 상시 '오늘' 스타일이 그대로인가

### 조건 성립을 먼저 증명한다

Phase C에서 **세 번** "통과/실패"가 사실은 조건 미성립이었다(컨테이너가 넘치지 않아 스크롤 이벤트가 없었음, 아래 공간이 남아 뒤집을 이유가 없었음, QA 이벤트가 다른 날에 있어 목록이 넘치지 않았음).

각 검증마다 **조건이 실제로 성립했는지 먼저 확인**한다 — `scrollTop`이 실제로 움직였는지, 목록이 실제로 넘쳤는지, 오늘이 실제로 화면 밖이었는지. 조건이 성립하지 않은 결과는 통과로 세지 않는다.

## 결정 로그

- **자동 소멸(2초 + 0.5초 페이드)**(사용자 결정) — "우리 방식대로 개선되어야 한다". 결과적으로 업스트림의 10곳 해제 로직을 전부 제거할 수 있게 됐다.
- **접근안 A(타이머만, 조기 해제 없음)**(사용자 승인, 3개 안 중) — 조기 해제(B)와 효과 기반 해제(C)가 푸는 문제를 타이머가 이미 없앴다. 남는 것은 일정 클릭 후 1~2초의 잔상뿐이고, 그것 때문에 열거식 해제를 도입하는 것은 YAGNI. **QA에서 잔상이 실제로 거슬리면 그때 B의 한 줄만 추가한다.**
- **목록 뷰의 스크롤이 우선**(사용자 증언) — 이 기능은 원래 목록 뷰 내비게이션을 위해 만들어졌다. 설계 판단이 갈리면 목록 뷰를 우선한다.
- **`clusterOpen`/`moreOpen` 불필요로 종결** — Phase C가 Phase B 의존으로 미뤄둔 항목. 해제 로직이 사라지면서 존재 이유가 없어졌다.
- **공개 옵션 없음, CSS 변수 하나만** — YAGNI. 지속 시간·on/off는 나중에 추가 가능한 변경이다.
- **종일 행 배경 레이어는 미리 결정하지 않는다** — calvue 구조가 업스트림과 다를 수 있으므로 구현 중 실제 증상을 보고 판단한다.
- vitest 도입은 범위 밖 — 기존 typecheck+build+플레이그라운드 스모크로 검증(Phase A·C와 동일).
