# Phase E — 시각 표기 규칙 통일과 `timeFormat` 옵션

## 배경: 원래 계획된 Phase E는 비어 있다

`saeroun-gw-web` 역이식 6개 phase 중 E는 "i18n"으로 잡혀 있었고, Phase A 스펙이 착수 전 재평가를 요구했다:

> Phase E(i18n 문구)는 재평가 필요: 원본 커밋(`bb67d9e65`)은 그룹웨어 자체 vue-i18n 키 전환이라 calvue의 독립적인 `CalMessages` 카탈로그와는 다른 축

조사 결과 **그 의심이 맞았다.** `bb67d9e65`는 전부 메커니즘 변경(하드코딩 한국어 → 자기네 vue-i18n 키)이고, 그 커밋이 새로 추가한 문구까지 포함해 전부 calvue에 이미 있다. calvue가 먼저 했다. **이식할 내용은 0건이다.**

대신 조사가 **같은 축의 실제 결함**을 찾아냈다. 이 스펙은 그것을 다룬다. upstream과 무관한 calvue 자체 작업이다.

## 문제

### 시각 표기가 뷰마다 다르고, 일부는 한 화면 안에서 섞인다

현재 상태의 정확한 지도:

| 뷰 | 자리 | 소스 | 현재 표기 |
|---|---|---|---|
| 월 | 이벤트 시각 | `m.eventTime` (`cal-month-view.vue:98`) | **12시간** `오전 9시` |
| 월 | 이벤트 바 | `m.eventTime` (`cal-event-bar.vue:16`) | **12시간** |
| 월 | `+N 더보기` 팝오버 | `m.dayLabel` (`cal-month-view.vue:131`) | **혼용** |
| 주/일 | 시간 눈금 | 하드코딩 (`cal-time-grid.vue:72`) | 24시간, **카탈로그 키 없음** |
| 주/일 | 시간 이벤트 바 | `m.gridTimeLabel` (`cal-time-grid.vue:113`) | 24시간 |
| 주/일 | 종일 행 이벤트 | — | **시각을 표시하지 않음** (아래 정정 참조) |
| 주/일 | 드래그·선택 프리뷰 | 하드코딩 `fmtMin` (`cal-time-grid.vue:128,297`) | 24시간 |
| 주/일 | 터치 클러스터 팝오버 | 하드코딩 (`cal-time-grid.vue:156`) | 24시간 |
| 목록 | 시각 칼럼 | `m.dayLabel` (`cal-list-view.vue:22`) | **혼용** |
| 전 뷰 | 툴팁 시작·종료 | 하드코딩 (`cal-tooltip.vue:10,13`) | `YYYY-MM-DD HH:mm`, **로케일 무관** |

"혼용"은 **한 함수 안**에서 갈린다. `koDayLabel`(`messages.ts:15-24`):

```ts
if (startsHere && endsHere) return `${ev.start.format('HH:mm')}–${ev.end.format('HH:mm')}`; // 24시간
if (startsHere) return koEventTime(ev.start);                                              // 12시간
if (endsHere) return `${koEventTime(ev.end)} 종료`;                                        // 12시간
```

`enDayLabel`에도 같은 구조가 그대로 복제돼 있다. **`ko`와 `en` 양쪽 결함**이다.

브라우저에서 확인한 실제 출력(`locale: 'en'`, 목록 뷰, 세 줄 간격):

```
10일   10:00–11:00     ← 24시간
11일   10 PM           ← 12시간
13일   3 AM ends       ← 12시간
```

### ⚠️ 정정 — 주/일 종일 행은 원래 문제가 아니었다 (구현 중 발견)

이 스펙의 최초 감사 표는 주/일 종일 행을 **12시간**으로 적고, 바로 아래 시간 이벤트(24시간)와 어긋난다고 판단했다. **틀렸다.**

`cal-time-grid.vue:328`이 `allDayEvents = props.events.filter((e) => e.allDay)`라 **종일 행에는 `allDay: true` 이벤트만 들어간다.** 그런데 `cal-event-bar.vue`의 시각 span은 `v-if="!event.allDay && !continued"`로 막혀 있다. 즉 그 행이 담을 수 있는 **모든** 이벤트에서 시각이 아예 렌더링되지 않는다 — 12시간도 24시간도 아니다.

시간이 있는 멀티데이 이벤트는 종일 행이 아니라 **시간 그리드**로 간다(같은 파일 348행이 거기서 `allDay`를 제외한다). 거기 라벨은 `gridTimeLabel`이고, 이 함수는 **모든 분기가 원래부터 24시간**이었다.

**결론: 주/일 뷰에는 혼용이 없다.** 감사 표가 틀린 이유는 `cal-event-bar`의 소스가 월 뷰와 공유된다는 것만 보고 그 행에 실제로 어떤 이벤트가 도달하는지 확인하지 않았기 때문이다. 이 오류에서 나온 작업(종일 행에 24시간 라벨 전달)은 구현 후 되돌렸다.

깨진 곳은 **목록 뷰**와 **월 `+N 더보기` 팝오버**(둘 다 `dayLabel`), 그리고 **툴팁**(로케일 무관 하드코딩) 셋이다.

### 왜 지금까지 안 걸렸나

**플레이그라운드가 `locale`을 한 번도 넘기지 않는다.** `playground/main.ts`의 `<CalCalendar>`에 `:options`가 없어 `en` 경로가 개발 중 실행된 적이 없다. 이번 조사도 임시 패치를 해야 확인할 수 있었다.

### 그리고 12/24는 선택할 수 없다

12시간·24시간 선호는 언어와 독립적인 축이다(영어권 24시간 사용, 한국어권 12시간 사용 모두 흔하다). 그런데 지금은 이걸 바꾸려면 `CalMessages` 카탈로그 27개 키를 전부 채워야 한다. 사실상 불가능하다.

## 설계

### 규칙: 뷰별 관례를 기본값으로 삼는다

현재 상태가 전부 무질서한 건 아니다. **월 12시간 / 주·일 24시간**에는 이유가 있다:

- **월 뷰는 단일 시각을 여백 속에 하나 찍는다.** 대조할 기준 축이 없으니 `오전 9시`가 자연스럽다.
- **주/일 뷰에는 시간 눈금이라는 24시간 자가 화면에 있다.** 그 옆 이벤트 라벨이 12시간이면 눈금과 눈으로 대조되지 않는다.

따라서 **기본값은 이 규칙을 바꾸지 않고, 깨진 곳까지 일관되게 확장한다:**

| 뷰 | 기본 표기 |
|---|---|
| **월** | **12시간** (현행 유지) |
| **주/일** | **24시간** — 눈금·이벤트 바·프리뷰·클러스터 전부 (종일 행은 원래 시각을 표시하지 않는다) |
| **목록** | **24시간** |
| **툴팁** | 로케일 카탈로그를 따름 (`ko` 기본은 현행 `YYYY-MM-DD HH:mm` 유지) |

**목록 뷰를 24시간으로 정한 근거**(사용자 결정): 기준 축이 없다는 점은 월 뷰와 같지만, 목록은 **범위**를 100px 고정 칼럼(`.time { width: 100px }`)에 찍는다. 12시간 범위는 압축형(`오후 2–3시`)을 새로 만들어도 폭이 빠듯하고, 무엇보다 주/일과 목록을 오갈 때 같은 이벤트가 다르게 보이는 게 어색하다.

### `timeFormat` 옵션

```ts
// src/types.ts — CalTooltipField와 같은 자리에 정의
export type TimeFormat = 'auto' | '12h' | '24h';

// CalOptions
timeFormat: TimeFormat;   // 기본 'auto'
```

**`src/index.ts`에서 내보내지 않는다.** 같은 성격의 `CalTooltipField`도 내보내지 않고 있고, 소비자가 `{ timeFormat: '12h' }`처럼 리터럴로 쓰면 구조적 타이핑으로 통과한다. 공개 export 목록을 늘리는 건 별도 판단이 필요한 일이라 이 스펙 범위 밖으로 둔다.

- `'auto'` — 위 표의 뷰별 관례
- `'12h'` — **전 뷰** 12시간
- `'24h'` — **전 뷰** 24시간

`DEFAULT_CAL_OPTIONS`가 이미 모든 옵션을 명시적으로 채우므로(`locale: 'ko'` 등) `'auto'`도 명시적 기본값으로 둔다. `undefined`가 auto를 의미하는 3-상태보다 타입과 기본값 객체에서 자기설명적이다.

### 우선순위 — 기존 계층에 한 겹 삽입

```
locale        카탈로그 선택        (ko | en | 그 외 → ko)
   ↓
timeFormat    카탈로그 내 변형 선택  (auto | 12h | 24h)
   ↓
messages      개별 키 덮어쓰기       ← 명시적 지정이 항상 이긴다
```

`messages`로 포맷터를 직접 넘긴 소비자에게는 `timeFormat`이 영향을 주지 않는다. 이게 옳다 — 명시적 함수를 옵션이 덮어쓰면 소비자가 통제권을 잃는다.

구현은 내부 리졸버 시그니처 확장으로 끝난다:

```ts
export function resolveMessages(
  locale: string,
  overrides?: Partial<CalMessages>,
  timeFormat: TimeFormat = 'auto'
): CalMessages
```

`resolveMessages`는 **공개 export가 아니다**(`src/index.ts`는 컴포넌트 2개 + 타입 8개만 내보낸다). 시그니처 변경은 비파괴적이다.

### 새 카탈로그 키 2개

하드코딩된 네 자리를 카탈로그로 끌어올린다. 개별 포맷터 3~4개를 나열하는 대신 **시계 표기 프리미티브 하나**로 묶는다:

```ts
/** 시:분 한 지점. 눈금·드래그 프리뷰·클러스터 팝오버가 공유한다. */
clockTime: (hour: number, minute: number) => string;

/** 툴팁의 날짜+시각. 날짜가 필요해 clockTime과 분리한다. */
tooltipDateTime: (d: Dayjs) => string;
```

`clockTime`이 `Dayjs`가 아니라 `(hour, minute)`을 받는 이유: 드래그 프리뷰의 `fmtMin`(`cal-time-grid.vue:277`)은 **자정 기준 분(minute-of-day)**만 들고 있고 `Dayjs`가 없다. 날짜 포맷터가 아니라 시계 프리미티브라는 걸 시그니처가 드러내는 편이 정직하다.

호출부:

| 자리 | 변경 |
|---|---|
| 눈금 `cal-time-grid.vue:72` | `m.clockTime(h, 0)` |
| `fmtMin` `cal-time-grid.vue:277` | `m.clockTime(Math.floor(t / 60), t % 60)` |
| 클러스터 `cal-time-grid.vue:156` | `m.clockTime(...)–m.clockTime(...)` |
| 툴팁 `cal-tooltip.vue:10,13` | `m.tooltipDateTime(...)` |

기존 `eventTime` / `dayLabel` / `gridTimeLabel`은 **키를 유지하고 내부만 정리**한다 — 한 함수 안에서 분기마다 표기가 갈리지 않게.

### `cal-time-event.vue:43`의 죽은 폴백

`props.timeLabel ?? \`${...format('HH:mm')}–...\`` 형태인데, 유일한 호출부(`cal-time-grid.vue:113`)가 **항상** `time-label`을 넘기므로 폴백은 도달 불가능하다. 하드코딩을 남겨두면 나중에 누군가 되살릴 때 규칙 밖으로 샌다. 폴백을 제거하고 `timeLabel`을 필수 prop으로 바꾼다.

## 공개 API 변경

### 추가

| 항목 | 타입 | 기본값 |
|---|---|---|
| `CalOptions.timeFormat` | `'auto' \| '12h' \| '24h'` | `'auto'` |
| `CalMessages.clockTime` | `(hour: number, minute: number) => string` | 로케일·timeFormat별 |
| `CalMessages.tooltipDateTime` | `(d: Dayjs) => string` | 로케일·timeFormat별 |

`CalMiniMonth`는 시각을 렌더링하지 않으므로 `CalMiniOptions`는 건드리지 않는다.

### ⚠️ `CalMessages` 키 추가의 두 갈래 영향

`CalMessages`는 **공개 타입**이다(`src/index.ts`). 키가 27 → 29개가 되면서 소비자가 셋으로 갈린다:

- **`Partial<CalMessages>`로 일부만 덮어쓴 소비자** — 영향 없음.
- **`CalMessages` 전체를 타이핑한 소비자** — **컴파일 에러.** 새 키 2개를 추가해야 한다.
- **완전한 커스텀 로케일을 `messages`로 공급한 소비자** — `messages`는 얕은 병합이라 **타입 에러 없이 한국어 기본값으로 조용히 폴백**한다. `noEventsOnDay`(v0.3.0)와 같은 함정이며, 이번엔 2개다.

세 번째가 가장 위험하다. v0.3.0에서 `noEventsOnDay`에 대해 한 것과 동일하게 README에 명시하고 릴리스 노트 상단에 올린다.

## 동작 변화 — 코드를 안 바꿔도 화면이 달라지는 것

기본 옵션(`locale: 'ko'`, `timeFormat: 'auto'`) 기준:

| 자리 | 이전 | 이후 |
|---|---|---|
| 목록 뷰, 시작만 걸친 이벤트 | `오후 10시` | `22:00` |
| 목록 뷰, 끝만 걸친 이벤트 | `오후 3시 종료` | `15:00 종료` |
| 월 `+N 더보기` 팝오버 | 위와 동일 | 위와 동일 |
| **월 뷰 이벤트 시각** | `오전 9시` | **변화 없음** |
| **주/일 뷰 전체** | 이미 24시간 | **변화 없음** (위 정정 참조) |
| **목록 뷰 당일 이벤트** | `14:00–15:00` | **변화 없음** |
| **툴팁 (`ko`)** | `2026-08-25 11:00` | **변화 없음** |

`en` 소비자는 위에 더해 툴팁·눈금이 `en` 관례를 따르게 되므로 변화 폭이 더 크다. 다만 `en`은 애초에 내부적으로 깨져 있었다.

**가장 흔한 케이스(당일 시간 이벤트)와 월 뷰는 그대로다.** 바뀌는 건 멀티데이 이벤트가 걸친 날의 행뿐이다.

## 측정이 필요한 미해결 지점

**`timeFormat: '12h'`일 때 주/일 눈금이 넘칠 수 있다.**

눈금 폭은 `--cal-gutter` 기본 56px, `max-width: 600px`에서 42px. `padding-right`(6px/4px)를 빼면 가용 폭은 약 50px / 38px이고 글꼴은 11px / 10px이다.

| 표기 | 대략 폭 | 기본(50px) | 좁은 폭(38px) |
|---|---|---|---|
| `09:00` | ~30px | ✓ | ✓ |
| `9 AM` | ~28px | ✓ | ✓ |
| `12 PM` | ~34px | ✓ | ✓ |
| `오전 9시` | ~44px | ✓ | **✗** |
| `오후 12시` | ~48px | 빠듯 | **✗** |

**추정치다. 구현 시 실측해야 한다.** 대응 후보는 (a) `'12h'`일 때 `--cal-gutter` 상향, (b) 한국어 12시간 눈금만 압축형(`오전 9`), (c) 눈금은 `'12h'`에서도 24시간 유지. 실측 후 결정한다.

`'auto'`(기본값)에서는 눈금이 24시간이므로 **이 문제는 옵션을 명시한 소비자에게만 발생한다.**

## 검증

이 저장소에는 테스트 프레임워크가 없다(의도된 상태). `yarn typecheck` + `yarn build` + Playwright 브라우저 QA가 게이트다.

**이번 작업은 순수 문자열 출력이라 typecheck이 거의 잡아주지 못한다.** 특히 "한 함수 안에서 분기마다 표기가 갈리는" 결함은 타입이 전부 `string`이라 구조적으로 안 걸린다. 브라우저 QA가 사실상 유일한 게이트다.

**조건을 먼저 성립시켜야 하는 케이스**(이번 조사에서 실제로 겪었다 — 기본 픽스처로는 12시간 분기에 도달조차 못 했다):

- **시간이 있는 멀티데이 이벤트가 반드시 필요하다.** 종일 멀티데이로는 `dayLabel`의 12시간 분기에 도달하지 않는다.
- 이 이벤트는 목록 뷰와 월 `+N 더보기` 팝오버에 동시에 나타나야 두 자리를 한 번에 볼 수 있다. (주/일 종일 행은 대상이 아니다 — 위 정정 참조. 시간 멀티데이 이벤트는 시간 그리드로 간다.)

확인할 것:

1. **혼용 소멸** — `ko`·`en` 각각에서 목록 뷰 시각 칼럼 전체를 수집해 12시간 패턴과 24시간 패턴이 **동시에 나오지 않는지**. 이번 조사에서 쓴 검사 방식 그대로.
2. **뷰별 관례** — `'auto'`에서 월 12시간 / 주·일 24시간 / 목록 24시간
3. **옵션 전환** — `'12h'`·`'24h'` 각각에서 위 네 뷰 + 툴팁이 **전부** 해당 표기
4. **눈금 실측** — `'12h'` × `ko` × 기본/좁은 폭에서 `.tg-hour`의 `scrollWidth > clientWidth` 여부
5. **우선순위** — `messages`로 `clockTime`을 넘기면 `timeFormat`과 무관하게 그게 나오는지
6. **회귀** — 기본 옵션에서 월 뷰 이벤트 시각과 목록 당일 이벤트가 v0.3.0과 동일한지

### 플레이그라운드에 `?locale=` · `?timeFormat=` 추가

이 결함이 살아남은 원인이 "`en` 경로가 개발 중 실행된 적 없음"이므로, **원인 자체를 고친다.** `playground/main.ts`가 `view`를 쿼리스트링으로 받는 것과 같은 방식으로 `locale`·`timeFormat`도 받게 한다. 이후 QA가 임시 패치 없이 가능해진다.

## 범위 밖

- **`cal-mini-month.vue:4,6`의 `aria-label` 누락** — 조사 중 발견했으나 i18n이 아니라 접근성이다. 보류 중인 Phase D 소관.
- **날짜(연·월·일) 표기** — `monthTitle`·`weekTitle`·`popoverDate`·`listMonthHeader`가 이미 카탈로그에서 나오고 혼용이 없다.
- **`ja` 등 내장 로케일 추가** — 별건.

## 결정 로그

- **Phase E의 원래 범위(upstream `bb67d9e65` 이식)는 폐기.** 조사 결과 이식할 내용 0건. 이 스펙이 그 슬롯을 대체한다.
- **12/24를 옵션으로 뽑는다**(사용자 제안). 증상만 맞추는 것보다 낫다 — 모든 시각 출력이 한 포맷터를 지나가야 해서 혼용이 구조적으로 불가능해지고, 언어와 독립적인 선호 축이 열린다.
- **기본값은 뷰별 관례 유지**(월 12시간 / 주·일 24시간). 사용자가 월 뷰의 `오전 9시`를 적절하다고 확인했고, 주/일 24시간에는 눈금이라는 구조적 근거가 있다.
- **목록 뷰는 24시간**(사용자 결정) — 100px 고정 칼럼에 범위를 찍고, 주/일과 표기가 일치해야 한다.
- **`messages`가 `timeFormat`을 이긴다** — 명시적 지정이 옵션에 지지 않는다.
- **키를 3~4개 나열하는 대신 `clockTime` 프리미티브 하나로 묶는다** — 눈금·프리뷰·클러스터가 같은 규칙을 공유하게 강제된다.
